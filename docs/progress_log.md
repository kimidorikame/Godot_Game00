## 追記（2026-08-11・続き）: 困窮脱出動線の土台（鍋の日またぎ持ち越し）

**やったこと**

困窮脱出動線（クズ食材ベース）の検討に着手。まず現状の棚卸しを行い、構想と現状コードの差分を把握した。

重要な発見: 現状の「残り湯」（`base_zanryu.tres`）は「その日限りの固定の薄いベース」で、構想の「前日の鍋を持ち越して薄める」とは名前が同じだけの別物だった。鍋は毎晩使い捨てで、日をまたぐと状態が消える実装になっていた。

この棚卸しを踏まえ、構想を3段階の救済ハッチとして再定義した（詳細は `docs/poverty_fallback_design.md` に記録）。そのうち全機構が共通して必要とする土台「鍋の日またぎ持ち越し」を実装・コミット（`619e93a`）。

1. **GameStateに持ち越しフィールドを追加**
   `pot_carryover_volume` / `pot_carryover_rich` / `pot_carryover_light` / `pot_carryover_umami`（すべてint）を新設。営業終了時点の鍋を加工せずそのまま保存する

2. **`night/game.gd` にスナップショット処理を追加**
   `end_day()` から `_snapshot_pot_to_gamestate()` を切り出し、`_pot` の状態をGameStateに書き込む。`_pot == null`（営業が一度も始まらなかった日）なら明示的に0を書き、前日以前の古いスナップショットが残留しないようにした

3. **save/loadに4フィールドを追加**
   `load_game()` は `.get(key, 0)` で読むため、この4フィールド追加前の旧セーブを読んでも0（持ち越しなし）で復元され、クラッシュしない

4. **今日のセーブ基盤との連携**
   `_finalize_day_and_save()` の `day==7` 判定（前回のセーブUX調整で導入済み）のおかげで、Day7の鍋はそもそも保存されない。追加のDay7ガードは不要だった

5. **テスト・実機確認**
   自動テスト（`_snapshot_pot_to_gamestate()` のシーン外テスト8項目、save/load往復＋旧形式互換13項目）全PASS。旧形式互換テストは手元に実際に残っていた旧セーブ（Day4・money3075の実プレイデータ）を使って検証した。実機でも「1杯提供ぶんvolumeが減った状態で翌日に持ち越される」辻褄が合うことを確認

**設計方針**: 鍋を素のまま持ち越すことで、「連続使用でさらに薄くなる」累積劣化を後日自然に表現できるようにする布石とした。

**保留・次の一手**

- 応用（今日のスコープ外、次回以降）: 持ち越した鍋を残り湯として薄める処理、残り湯の連続使用劣化、クズ食材ベースの入手動線、それらのUI・評価影響。詳細な仕様は `docs/poverty_fallback_design.md` に記録済み
- 棚卸しで判明した既存の負債: 現状の `base_zanryu.tres` ベースの「残り湯」は構想と別物なので、応用実装時に整理が要る
- 既存の無関係な警告（signal未使用、`ending_for_reputation` の STATIC_CALLED_ON_INSTANCE 等）がデバッガに出る。動作影響はないが、いずれ掃除する候補

**やったこと**

会話（シナリオ）仕様の検討に着手。Dialogicの機能と現状の実装を棚卸しし、会話構想を固めた。

1. 現状の夜営業は会話と調理が直列分離しており、コアビジョンの「ながら作業」は未実現
